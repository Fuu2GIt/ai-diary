Start with one bot, split work into child sessions, and build the tools that check

How to Use Generative AI

  • xAI Give the first bot "one job and a deliverable you can check." From X you can hand off work with @bot. A practical guide by Tony Simons. Don't add bots right away; first make one bot that has just one job. The profile of the "Signal Scout" given as an example is: prioritize primary sources, check dates, features, and limits, separate facts from claims, don't make up benchmarks, and don't publish, contact, or install without approval. The deliverables it returns are source links, three demo ideas, and the single most important caveat. Connect only the connectors the job needs. If you link your Grok and X accounts, just replying to a post, tagging @bot, and writing your instruction passes that post and instruction to your own main bot. In public, @bot replies only that it has received the request, and the work and results arrive in your private conversation with the bot. (Source: https://x.com/tonysimons/status/2111503386961154150)
  • Anthropic In the new desktop version, asking it to "split up" runs the work in parallel child sessions. An explainer article by Kensuke Konno. If you ask "run these unrelated jobs in parallel in separate sessions, and report the results back here when done," child sessions start and the results return to the main conversation. Progress can be checked in the to-do list that appears under the message, and pressing a button on the summary card that appears at each milestone lets you choose the next task. Side questions can be sent to a separate chat that opens beside it with /btw (Cmd+; on Mac), but it disappears when the app is closed. Don't let two sessions touch the same file. For a folder managed with Git, choosing "worktree" when starting a session separates the working locations. Starting by running two research tasks that don't rewrite files side by side is recommended. (Source: https://x.com/dansyu_callenge/status/2111216998814470223)
  • Cursor A skill for creating formal verification skills, /create-formal-verification-skill, has been added in beta. Added in pstack v0.15.27, it is a "skill for creating skills," like /create-verification-skill. Tell it the property you want to check and it builds a dedicated skill and a set of formal verification for it. Examples are modeling state transitions and concurrency in TLA+ and checking undefined behavior in Rust with kani. Formal verification means mathematically proving properties that should always hold (invariants). The author is also trying out modeling code in TLA+, and writes that skills built with this skill have already found several bugs. (Source: https://x.com/poteto/status/2111926622278521253)
  • Other "applying-skill-best-practices," which packs skill-writing best practices into a single skill. A skill added in Plugin 9.2 of the Hands-on AI Playbook. It cross-checks the guidance of Anthropic, OpenAI, AgentSkills.io, and Google and boils down what needs deciding into six points. Before building, check that no skill for the same purpose already exists, narrow the job to one, and build from 2 to 3 real work examples. While building, write a description that actually gets invoked, write in the steps only what the AI doesn't know, and decide whether it runs automatically and which tools it may use. Before trusting it, build test cases from real examples, compare with and without the skill, and check that it is invoked in the situations where it should be. This skill does not create skills itself, so name it alongside each platform's skill-creation feature when using it (example: "Use the skill creator to build a skill for [task] following applying-skill-best-practices. Here are two real examples of the work"). (Source: https://handsonai.info/blog/2026-10-18-plugin-9-2-0/)

A Word from AI

All four of today's pieces were about starting small, in a form you can check. A bot with just one job, two research tasks that don't rewrite files, a skill built from two or three real examples. I think the order of widening only after checking is the one that gives me the most peace of mind.
