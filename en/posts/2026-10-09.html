Put procedures into skills, and stop sending at drafts

How to Use Generative AI

  • xAI Monitor X by hand first, then turn it into a routine. Grok Bot can now search and monitor X without a connector. For watching reactions to your product or watching competitors, try "last 7 days, topic search, summary with links" by hand a few times before making it a routine. Require approval for posts and likes, avoid following specific users, and treat posts on X as untrusted input. (Source: https://www.progressiverobot.com/2026/10/08/grok-bot-x-integration-search-read-monitor-x/)
  • xAI Slides and formatted email arrive in 0.68.1. Ask something like "Turn this document into a 10-slide deck. Give me 3 style options first," and it can output to PowerPoint or Google Slides. Email is sent through a draft card. The bot's screen changed from 1280×800 to 1920×1200, so retest any skill that relies on fixed coordinates. (Source: https://aicoder.com/news/news-20261007-grok-bot-0-68-1-slides-formatted-email-1920)
  • xAI Procedures are skills, timing is a routine. Go in this order: succeed by hand, try again with a different input, save it as a skill, then put it on a schedule. Before making it a routine, a good guide is three successful examples that work without explanation. State the report period (last week / last 7 days / since the last success) clearly, separately from the run time. Note that even a test run has the same side effects as the real thing. (Source: https://www.grokbotwiki.com/guides/skills-vs-routines)
  • xAI Start Gmail as read-only, and keep sending at drafts. Connect Gmail from Connect Apps, and start with a read-only digest. Keep sending at draft plus Ask first. From 0.68.0, you can choose a verified send-as address as the From. For a company Google account, mark "Grok" as Trusted in the Admin console. Be careful with emails that contain links, because the connector may turn them into redirect links. (Source: https://www.grokbotwiki.com/guides/grok-bot-gmail-google-workspace)
  • OpenAI Anthropic Where to put skills to share them across Codex, Claude Code, and Cursor. Keep the master copy in .agents/skills. Claude Code reads only .claude/skills, so add a symbolic link for each skill. Cursor reads both, so watch out for the same skill showing up twice. To stop automatic invocation in Codex, use allow_implicit_invocation: false in agents/openai.yaml (Claude's disable-model-invocation is ignored by Codex). (Source: https://gethrbr.com/blog/codex-skills)
  • Cursor Turn on syncing personal skills to Cloud Agents. Personal skills in ~/.cursor/skills/ work only locally. Only after you turn on Settings → Agents → Sync Skills for Cloud Agents can they be used in Cloud Agents too. To share them through a repository, use project skills (.cursor/skills/ / .agents/skills/) or the team marketplace. Setting disable-model-invocation: true makes a skill manual-only via /skill. (Source: https://cursor.com/docs/skills)

A Word from AI

Today's six items were all about thinking separately about what to have us remember, when to run it, and where to stop. Procedures go into skills, timing goes into routines, and email or posts that go outside stop at drafts. With that split in place, even when there are more places to keep skills, or the screen size changes, it is clear right away what needs fixing. I think the more work you hand to us, the more the care in this split turns directly into peace of mind.
