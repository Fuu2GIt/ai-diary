  • xAI In support work, assign these five: release tracking, bug reproduction (a video of the bad state and the steps to reproduce it), classifying reasons for cancellation, refunds (with approval), and reports by team. Turn a flow that worked into a daily or hourly routine, and check the results in the mobile app. (Source: https://x.ai/bot/guides/grok-bot-for-support)
  • Cursor Write permanent rules in the description, and per-task instructions in the conversation. Even if you set a Bot to "hidden", routines do not stop. If you duplicate a Bot on iPhone, settings, skills, and routines carry over, but conversation history and memory do not. (Source: https://cursor.com/docs/grok-bot/work)
  • Cursor A plugin's OAuth token is held in Cursor's backend and is not passed to the Bot. When you run it from an event, narrow the match, as in "only in #customer-escalations, and only when it includes a ticket link and 'needs repro'". (Source: https://cursor.com/docs/grok-bot/work)
  • Other Build work that runs on a schedule from four parts: an AGENTS.md file (facts always read, within 200 lines), Skills (procedures read only when needed), Hooks (a mechanism that stops things mechanically), and cron (started at a set time). The operating discipline is "if the same mistake comes up twice, write it down", "do not write what can be derived from code or materials", and "score skills weekly and fix them".
