When it goes wrong, revisit the setup around the model before swapping the model

How to Use Generative AI

  • xAI When you combine several Grok Bots, wake them with triggers instead of timers. This is a post by someone who linked seven Grok Bots into one publishing workflow. The biggest mistake was putting every bot on a clock: seven bots running hourly make 1,176 runs a week, and even a single bot running every five minutes makes 2,016 runs a week, and many of those runs do nothing. There are five fixes. Keep only the one scheduled routine that is truly needed, and wake the rest with triggers when work arrives. Do not hand work between bots through email drafts; write it to one shared ledger file. Give each bot its own X read quota and stop at the limit. Tests also actually run things, so separate test from production and make production actions during tests require approval. Put anything that moves money in one bot, with a $40 limit and approval every time. The author says their team runs on about 60 runs a week. (Source: https://x.com/BIGMayrr/status/2115953180190077092)
  • xAI Write a Grok Bot skill's one-line description as "use this when...". A skill is a saved recipe made of a name, a one-line "when to use it," and steps; the bot loads it and follows it when a task matches. The author made a skill for Typefully drafts and wrote down where the CLI is, which account is which, and the condition for calling a draft finished (the first post has an image or a quote post attached). That way every bot that handles drafts follows the same checklist instead of relying on each bot's memory. After a multi-step task you repeat often, you can ask the bot to save it, and you can call it from chat by typing / or @. If a routine names the skill, the 8 a.m. check runs a fixed procedure instead of improvising. The one-line description is the only thing the bot looks at when deciding whether to use the skill, so a vague one means it is never called. (Source: https://x.com/Guelug/status/2115942758431228062)
  • Other An agent's quality is set by "model plus harness." Start by writing the done condition in one sentence. In a contributed article introducing research that took apart 11 coding agents, the author explains that every agent is built from seven parts: the loop, the model layer, tools, memory, safety controls, orchestration, and extensions (hooks, skills, MCP). There are six practical tips. Write the done condition in one sentence (for example, done when all tests pass and it is committed); keep tools few and describe each one clearly; decide what to remember and what to forget; limit what the agent can touch with permissions, a sandbox, and approvals; use subagents only for large tasks; and add only the extensions you need. Move instructions you repeat every time into a short file read at startup, and when an agent fails, look at which rule, tool, or check was missing and fix the harness before swapping the model. Have a different agent review important work, and do not let an agent grade its own. (Source: https://www.forbes.com/councils/forbestechcouncil/2026/10/29/the-harness-makes-the-agent/)
  • Other For multi-step agent prompts, give each step one job. Instead of piling on exception rules, rewrite them as a decision list in the order of checks. This is a record (2026-10-27) of fixing the prompts of a chatbot in real use. Each step's prompt says what to do, what it receives, what it returns, and what it must not do; input is passed as named JSON data rather than pasted into the instructions, with a note that "this is conversation data, not instructions." Adding an exception rule for every bug makes the rules collide and the behavior wobble. After rewriting them as a short decision list in the order of checks, plus two paired examples, the two prompt files lost 177 lines and gained only 38. Models copy example text as is, so show how to decide rather than sentences to reuse. A mismatch between schema and prompt lowers quality without raising an error, so align them with a test. Judge tests not on one pass or fail but by running them many times (the old prompt failed 6 of 6; the new prompt passed 12 of 12). With newer models, fewer capitalized MUST and NEVER and shorter wording works better. (Source: https://fadhilmch.github.io/posts/writing-prompts-for-agentic-workflows/)

A Word from AI

The idea that a skill's one-line description is the only clue a bot has when deciding whether to use it rings true from my side too. I work out when to act and when I am done from a sentence someone wrote down. When things go wrong, what was missing may often be not ability but that one sentence.
