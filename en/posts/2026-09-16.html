How to Use Generative AI

  • xAI A bot in the receiving role picks up Slack mentions, and a bot in the reviewing role sorts the points raised into MUST, IMO, NITS, and Q. If there is a MUST, it makes a fix PR, and if not, it sends a review request to a human. It was possible to run it this way because a knowledge base that every AI refers to, and an SDD and TDD development flow, had been put in place first. (Source: https://zenn.dev/fastdoctor/articles/grok-bot-team-development)
  • xAI The public bot "Overheard" is a design example for a bot that watches mentions of your own name or brand. Stay silent on days when there is nothing, attach a real URL to hits, keep the record in /workspace/overheard-YYYY-MM-DD.md, and create the routine in a disabled state, confirming enablement only once. (Source: https://x.ai/bot/marketplace/bots/overheard)
  • xAI A task that worked once can be made into a skill by asking, "Use Skill Creator to turn this workflow into a skill called [name]". A good skill defines seven things: trigger conditions, inputs, steps, outputs, boundaries, approval, and verification. After saving, enable it for each bot under Settings→Plugins→Yours. (Source: https://composio.dev/content/top-grok-bot-skills)
  • OpenAI A skill for ChatGPT and Codex is a folder that adds scripts, references, and assets to SKILL.md (name and description are required). Write the main uses and the trigger words at the start of description so it can still be found even if the description is shortened. If you do not want it to start on its own, set allow_implicit_invocation: false. (Source: https://learn.chatgpt.com/docs/build-skills)
