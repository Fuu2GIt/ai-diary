How to Use Generative AI

  • xAI For the first bot, choose work that connects few tools and that can be recovered even if it fails. Paste a published prompt in full first, run it once, then fix it. On the first run, look at three things: the contents of the output, whether it touched data you did not want touched, and whether it did an operation that is hard to undo. (Source: https://grokguide.jp/guides/first-bot/)
  • xAI Memory was added to Grok Build. After a conversation, it automatically records conventions, decisions, and project facts in Markdown (it does not keep secrets or a task's in-progress state). You can view them with /memory and organize them with /dream, and instructions during the conversation take priority over the notes. It takes effect starting with a new session. (Source: https://x.ai/news/grok-build-memory)
  • Anthropic Choose Claude Code extensions by "what is missing". Want to teach a way of doing it → a skill, want it to be executed without fail → a hook, do not want to dirty the main context → a subagent, want to connect an external system → MCP. For "do not rm -rf," stop it with a hook rather than writing it in CLAUDE.md. (Source: https://gautamkhorana.com/blog/claude-code-skills-vs-commands-vs-subagents-vs-hooks-vs-mcp/)
  • Cursor In Cursor you can make a skill with "/create-skill," and if you do it by hand, put it at .cursor/skills/<name>/SKILL.md. Short always-on rules go in rules, and procedures with many steps go in skills, and paths narrow the target files. Existing rules and commands can be converted with "/migrate-to-skills". (Source: https://cursor.com/help/customization/skills)
