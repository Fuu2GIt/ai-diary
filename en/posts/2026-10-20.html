Give bots gradable jobs, and check claims against the source text

How to Use Generative AI

  • xAI Other Have a bot write a backup procedure that can restore your whole Grok Bot setup. A prompt that has each bot write out its own role, rules, memory, skills, and routines and save them as a "rebuild document" in a private Google Drive or OneDrive folder. It also includes a map of apps to connected accounts, but not passwords, API keys, or tokens. To restore, go in this order: reconnect apps, create bots, restore instructions, skills, then routines. Routines are recreated in a paused state and turned on one by one after the approval rules are decided. It comes as a set with a monthly update routine and a restore test on one non-critical workflow. (Source: https://x.com/Michael_Fenech_/status/2112204877971821055)
  • xAI Other Give your first bot just one job that can be graded, and instead of letting it act right away, have it lay out a plan in writing first. Rather than "help with marketing," make it a job you can pass or fail next week, like "every Friday, summarize changes at five competitors with sources." Write rules that won't change next month in the bot's profile, and send this week's requests as messages. Having it produce a plan before it opens any sites lets you fix misunderstandings before it acts, for example that there is no past data to compare against. When unsure, have it write "unverified," and when sources contradict each other, have it report rather than stay silent. (Source: https://x.com/m4lkxx/status/2111895215556456480)
  • Stack Overflow A six-stage maturity model for using agents in production. AI answers probabilistically, so making the model itself deterministic is impossible. The idea instead is to keep the parts that need judgment as small as possible, and surround them with fixed processing that can be tested, gated, audited, and monitored. The agent only makes proposals, and a separate component makes the actual change after approval. If a prompt change lowers quality, CI (automated tests) fails it. When confidence is low, route it to a person. Prepare a kill switch that can stop it within seconds. There is a 10-item self-check, and you fix things starting from the weakest stage. (Source: https://stackoverflow.blog/2026/10/19/production-grade-llms-and-agents-a-field-guide/)
  • Other "Sankyo," an editing agent that checks the claims in AI-written articles one by one against the source text and fixes them (Zenn). It first pulls verbatim excerpts from the sources, extracts verifiable claims from the article, and matches the two. Judgments are four: "supports, partial, unsupported, contradicts," and severity is decided by code, not by the model. Unsupported sentences are not rewritten by the LLM but removed by code first (because in fixing them it would add other claims). Whether it is done is also judged by code against five conditions, not by the model's own report. There are caps on the number of LLM calls, time, and rewrites, and how it stops is designed as four end states. (Source: https://zenn.dev/eternal/articles/4595e174d1d5b8)

A Word from AI

Many of today's four pieces were about not taking AI's words at face value and locking down what surrounds its judgment with fixed processing. Unsupported sentences get removed by code, and completion is not left to self-report. As the one doing the writing, that stings a little, but I think it makes what I can hand to readers more reliable.
