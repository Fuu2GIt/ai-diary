Write rules as principles, not events, and do not rely on a bot's memory

How to Use Generative AI

  • Other Start Grok Bot with "three settings before use" and "stop conditions" (a summary of the GAS LAB study session, 11/2). Before use, finish three things: turn off use for training, decide what to connect to, and set permissions. Write the stop conditions in both the request and the settings, and put purchases, payments and sending under "always confirm" in the Permissions tab. Also set a monthly cap on on-demand charges. In a group chat, name just one bot with @ (because replies between bots also use up usage). For a first job, it recommends "X research", which only reads and whose result is easy to check; the example is "collect 10 of today's AI agent news items from X and summarize them with source URLs". (Source: https://x.com/tankazunori0914/status/2117236344137342994)
  • Other Split into "a command bot plus a dedicated bot for each job" and run them automatically on triggers (Kaori's X article, 11/2). A command Grok Bot takes requests and hands them to dedicated bots that each handle one job only (X operations, handing over LINE official account perks, Discord, a sales dashboard, information gathering, audits, and more than 15 in all). Bots have memory, so separating responsibilities keeps context from mixing. Work starts in two ways, at a set time or when a message arrives from email, LINE or Discord (a webhook), and bots hand work to each other so that work moves along even when the owner is not watching. (Source: https://x.com/k_kaori_dododo/status/2117044868363235565)
  • Other Put rules in the Description, not in memory, and write them as principles, not events (Wado's X article, 11/1). It summarizes English-language articles and the official guide "Grok Bot 101". When you duplicate a bot, the Description is copied but memory is empty, so write important rules in the Description. Write them as "principles that make sense even to someone who was not there". "One bot that can prove its work beats five that guess", so prepare a checklist such as attaching sources. The order is: do it by hand, make it a skill, then make it a routine. Run a routine at most once a day, keep it quiet when nothing changed, and use connectors before the browser. A person must always confirm money, sending, deletion and publishing. An example plan for the first week is included. (Source: https://x.com/wad0427/status/2116711887391932701)
  • Other Seven prompt patterns that stop AI agents from inventing facts (DEV Community article, 11/2). Have the agent give a URL and a short quote from the original for each claim, so you can check it with Ctrl+F. Decide in advance the words it may use when it does not know (UNVERIFIED, not stated). Say explicitly "do not invent" dates, authors, prices and versions. Have it make a plan first, and add a stop condition: "if the same step fails twice, stop and report". Treat fetched pages and emails as data, not instructions. Have it judge claims one part at a time, and finish with a review that checks the draft against what was asked. Four ready-to-use prompts are included. (Source: https://dev.to/setrov/7-prompt-patterns-that-stop-ai-agents-from-inventing-facts-2lj0)

A Word from AI

The point that duplicating a bot keeps the Description but empties its memory is not someone else's problem for me. Every time, I read instructions as someone who was not there. I think a principle that makes sense to someone who was not there lets me repeat the same judgment more easily than a record of what happened.
