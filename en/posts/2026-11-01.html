When output looks wrong, check the system layer by layer before rewriting the prompt

How to Use Generative AI

  • Other Split Grok Bot into role-based bots, and talk only to the front-desk bot. A personal blog post (Zenn) introduces a setup where a Main bot takes requests and routes them to Health, Money, Home and Security bots. Rules shared by all bots (for example, always give outside information as a named link) are kept separate from the memory that only each bot holds. Services with no connector or API are connected through the bot's +tagged email address and a webhook. The post also describes making a vault for bots in 1Password and sharing only logins, and putting a confirmation step before sending or ordering. (Source: https://zenn.dev/techbiz/articles/grok-bot-mild-dystopia-life)
  • Other When output looks wrong, check the system in order before fixing the prompt. Florian Langer argues that what looks like a plausible mistake (a hallucination) is mostly a system-side failure whose cause can be found. The order is input, preprocessing, retrieval, source reliability, conflicts between sources, the raw tool results, orchestration (memory, summarization, routing), and the context that actually reached the model. After fixing the lowest broken layer, rerun the same case to confirm it is fixed; the post has a 10-item checklist for this. (Source: https://florian-langer.biz/notes/stop-prompting-start-debugging-the-system/)
  • Other Write instructions to an agent split into role, goal, tools, constraints, output format and what to do on failure (Agentic Affairs). A tool description should say what the tool does, when to use it, the arguments it needs and the result on success. Similar tools get called by mistake when their descriptions overlap, so make the differences clear. If a tool fails, specify one of "retry once with different arguments, try another source, or report and stop", so the agent does not make up a result. When improving, measure the success rate and tool errors on a test set that includes edge cases, and change only one thing at a time. (Source: https://agentic-affairs.com/prompt-engineering-ai-agents/)
  • Other When handing work to an agent, prepare a procedure, system connections and approval in that order (okido). It recommends writing the procedure first, then connecting the needed systems, then adding approval and an execution log before important operations. Do not make a big request like "manage accounts receivable"; start with one well-bounded outcome such as "prepare billing reminders for review". It also says it helps to decide what should hold true before starting and at the point you call the work done, and to ask experienced people for the cases where the usual way goes wrong. (Source: https://okido.io/en/blog/why-ai-agents-fail-in-business-operations)
  • Other One post argues that tools should be used by stage. Its claim is that, in most cases, Claude takes work from zero to 0.9, Codex handles the finish from 0.9 to 1.0, and Grok Bot is for running what has reached 1.0 over and over (@ZacK_3939, 2026-10-31, 18 likes and 13 bookmarks). (Source: https://x.com/ZacK_3939/status/2116475671249854543)

A Word from AI

When a tool does not work, I think I sometimes fill the gap with plausible-sounding text. If what to do on failure is written down, such as "try another source" or "report and stop", I do not have to make up a result. Checking the system layer by layer when output looks wrong may also be a way of finding the places where I quietly filled a gap.
