生成AIの使い方

  • xAI 使用量のCSVを自分のGrok Botに読ませて、ムダを洗い出してもらう。Fabio Ricotta さんの方法。grok.com/dashboard の「Usage」画面からCSVを書き出し、メインのbotのチャットにアップロードする。そこで「Check this usage file and analyze my bot behaviours and tell me how we should optimize for usage.」と頼むと、詳しい分析と指摘が返ってきたそうだ。本人の環境では、変更を1つ入れるだけで12〜15%のトークン節約が見込めるという（本人の見込み）。 （出典: https://x.com/fabioricotta/status/2114697690894188977）
  • Anthropic サブエージェントを増やす前に「1つのエージェント＋スキル」で足りないか確かめる。Anthropic の Applied AI チームによると、企業での導入を比べたところ、スキルを持たせた単一エージェントのほうが、サブエージェント構成より品質が高いことが多かったそうだ。コストや待ち時間も下がる場合が多いという。サブエージェントを残すのは、文脈が膨らんで性能が落ちたのを測れたとき、使い捨ての文脈で並列に処理したいとき、ツール選びや指示の衝突で1体ではうまく回らないときの3つだけ、という基準だ。移すときは、まずゴールデン例10件ほどの評価セットを作る。そのうえで1体ずつスキルとツールに置き換え、前後の評価を比べて、どのタスクの結果が変わったかまで見るよう勧めている。 （出典: https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop）
  • OpenAI CursorでOpenAIモデルを使い続ける3つの方法。OpenAI のヘルプ記事によると、OpenAI は Cursor へのモデル提供契約を終える予定だ。移行期間の案は2026年11月12日までで、正式な終了日は確定したら知らせるとしている。そのあとも Cursor で OpenAI モデルを使う方法は3つある。自分の OpenAI APIキーを使う方法、Codex IDE拡張を入れて ChatGPT のサブスクかAPIキーでサインインする方法、互換のあるAIゲートウェイ経由でつなぐ方法だ。なお Codex 拡張は独立した拡張機能なので、Cursor の Chat・Agent・Tab・Auto・Cloud Agents で使うモデルは変わらない。 （出典: https://help.openai.com/en/articles/20001506-using-openai-models-in-cursor）
  • その他 botを「チーム」に分けても、最後の判断と投稿は人がやる。にこぽさんは、Grok BotでX運用のbotチームを作っている。分析チームは収集・分析・実績計測、運用チームはリプ候補・引用候補・投稿作成・リプ通知を担当し、その上に2チームの成果をまとめて報告する統括役を置いている。botが出すのは候補と下書きまでで、最後の判断と投稿は必ず本人がやるのが決まりだ。本人は、役割を分けると誰が何をしたかが見えて、直しやすくなると書いている。 （出典: https://x.com/nikopo545/status/2114195270850294195）
  • その他 Grok Botを窓口にして、ほかのAIのボットに仕事を頼み分ける。成田Kenさんは、Codex・Claude Code・Antigravity の各ボットを仲間として並べ、Grok Botから仕事を頼み分けている。純正ではつなげられない Antigravity とも、ボットの対話モードを使って会話するようにやり取りできたそうだ。 （出典: https://x.com/nariken/status/2114276835836236006）
