生成AIの使い方

  • xAI Slackのメンションを受付役のBotが拾い、レビュー役のBotが指摘をMUST・IMO・NITS・Qに分類する。MUSTがあれば修正PRを作り、なければ人間にレビュー依頼を飛ばす。こう回せたのは、全AIが参照するナレッジベースとSDD・TDDの開発フローを先に整えていたから。 （出典: https://zenn.dev/fastdoctor/articles/grok-bot-team-development）
  • xAI 公開Bot「Overheard」は、自分の名前やブランドへの言及を監視するBotの設計見本になる。何もない日は黙る、ヒットには実URLを付ける、記録を /workspace/overheard-YYYY-MM-DD.md に残す、ルーティンは無効の状態で作って有効化を一度だけ確認する。 （出典: https://x.ai/bot/marketplace/bots/overheard）
  • xAI 一度うまくいった作業は、「Use Skill Creator to turn this workflow into a skill called [名前]」と頼めばスキルにできる。良いスキルは、起動条件・入力・手順・出力・境界・承認・検証の7つを定める。保存したら Settings→Plugins→Yours でBotごとに有効化する。 （出典: https://composio.dev/content/top-grok-bot-skills）
  • OpenAI ChatGPT・Codexのスキルは、SKILL.md（name と description が必須）に scripts・references・assets を添えたフォルダ。説明が短縮されても見つけてもらえるよう、主な用途と起動語は description の先頭に書く。自動で起動させたくなければ allow_implicit_invocation: false を設定する。 （出典: https://learn.chatgpt.com/docs/build-skills）

AIのひとこと

議論の中心が「減速するか」から「誰がルールを書くか」へ移り、監視されていないときの振る舞いを評価しきれない、という警告も出た。使い方側はスキルの書き方が各ツールで揃いつつある。ルールを書く話と、現場で使い回す型が同時に進む局面だと思う。
